# Shiori Development Rules

## Code Rules

### Async/Await
- Always write asynchronous code using `async/await`.
- Never use callback style.
- Prefer `Promise.all` for parallel operations where applicable.

### Separation of Concerns
- **Controllers** must not contain business logic. They handle routing parameters, schema parsing/validation, calling services, and formatting HTTP responses.
- **Services** contain all business logic, third-party API calls, and calculations.
- **Models** define DB schemas, schema options, virtuals, indexes, and middlewares.

### Validation
- Validate all incoming route inputs (req.body, req.params, req.query) using **Zod**.
- Never trust client input. Sanitization and validation must happen at the entry controller level.

### Error Handling
- Use the global `errorHandler` middleware.
- Throw operational errors using the `AppError` class, which takes a message and an HTTP status code.
- Unhandled rejections and exceptions are logged via Pino.

---

## Security Rules

- **Env Configuration**: Never commit `.env` or files containing secret strings. Add them to `.gitignore`.
- **No Password/Credentials Storage**: External authentication is handled entirely by Supabase. Never store raw user passwords or user session/refresh tokens in our MongoDB database.
- **No Temporary URL Storage**: Streaming HLS/M3U8 URLs generated by providers are temporary and expire. Do not store these URLs in the database. Resolve them dynamically on demand and discard them.
- **No Unnecessary Scraped Data**: Keep database collections clean and focused. Avoid storing heavy, transient scraped payloads in MongoDB.
